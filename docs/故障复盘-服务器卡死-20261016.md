# 故障复盘：2026-10-16 服务器「掉了一段时间」

## 现象
用户反馈（17:40）：服务器掉了一段时间。表现为：网站 / 相册 / 音乐 / 监控台等 .164 上的服务短时无法访问，SMB 共享卡住。

## 结论
**不是网络故障，也不是磁盘故障 —— 是 .164 内存被量化回测任务打爆，整机在交换区抖动（thrashing）约 1 小时。**

## 证据链（.164 = user-web，Celeron J1900 / 3.8G 内存 / 1.5G zram）
| 时间 | 事件 |
|---|---|
| 16:29:02 | OOM #1：杀 python（RSS 1.40 GB） |
| 16:44:02 | OOM #2：杀 python（RSS 850 MB） |
| 16:54:27 | .223 上 SMB 挂载 .164「has not responded in 180 seconds」 |
| 16:56:43 | OOM #3：杀 python（RSS 940 MB） |
| 17:00:00 | 又一次 SMB 180 秒无响应（`close cached dir rc -11`） |
| 17:13:40 | casaos.service 被内存压力拖挂（Failed with result exit-code） |
| 17:26:51 | OOM #4：杀 python（RSS 888 MB） |
| 17:44 | 处理前：交换区 1535MB 用满、仅剩 44MB；15 分钟负载均值一度 54.41（4 核机器） |

## 根因
`/tmp/sim/overnight.sh`（另一窗口在跑的 A 股量化研究流水线，4 阶段）用
`docker run --rm -v /opt/aqf-research/current:/app:ro -v /tmp/sim:/sim ... python:3.12-alpine python -u <脚本>`
起临时容器跑回测。**容器没有任何内存上限**，加载 `dataset.json`（193MB）+ `snapshot.sqlite`（657MB）后每个进程吃 0.8–1.4 GB；
而 .164 只有 3.8 GB 物理内存 + 1.5 GB zram（内存压缩，不是真磁盘交换），两者都满 → 内核 global OOM，整机卡死。
OOM 日志特征：`constraint=CONSTRAINT_NONE ... global_oom`（没有 cgroup 限制 → 属于全局内存耗尽）。

## 处理（已做完并验证）
1. **加 4GB 交换文件**：`/nas/swapfile`（3TB 数据盘，ext4，顺序写 ~150MB/s），`swapon -p 10`（zram 优先级 100 先于它），写入 `/etc/fstab` 持久化。
   → 换页空间空闲从 **44MB → 3.8GB**
2. **内存策略** `/etc/sysctl.d/99-homelab-mem.conf`：`vm.swappiness=20`、`vm.vfs_cache_pressure=60`、`vm.min_free_kbytes=65536`
3. **守门员** `/usr/local/bin/sim-memcap.sh` + `sim-memcap.timer`（20 秒一次）：凡是 `python:3.12-alpine` 镜像起的容器，若 `HostConfig.Memory==0` 就自动 `docker update --memory 1600m --memory-swap 3200m`。
   **只作用于回测容器，不影响 NPM / 相册 / 音乐 / 监控台等正式服务**；容器超限只会杀容器内进程，不会拖死整机。
4. 验证：近 8 分钟 **0 次 OOM**；1 分钟负载 54 → 2.9；可用内存 568MB → 814MB；网站/监控台/主页全部 200。

## 建议（根治）
- **加一根内存条（强烈推荐）**：.164 主板 **2 个 DDR3 SO-DIMM 槽，最大 8GB**，现在只插了 1 根 4GB（Tigo-1600MHz-4G），**A1_DIMM1 空着**。
  买一根 4GB **DDR3L 1600 SO-DIMM（PC3L-12800S，1.35V 笔记本内存）**插上即 8GB。比换系统盘简单得多，也不影响系统。
- 或把量化回测挪到 .223（15GB 内存 / i5-8279U）跑，但数据在 .164，需要走共享盘，可能更慢。
- 回退方法：`swapoff /nas/swapfile && rm /nas/swapfile`（并删 fstab 行）、`systemctl disable --now sim-memcap.timer`。

## 与其它问题的关系
本次与 .164 系统盘**写入只有 5.9MB/s** 的问题无关（那个是另一件事，当前无坏道、SMART 正常，不影响这次故障）。
