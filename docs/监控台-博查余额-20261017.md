# 内网监控台：博查搜索余额卡片（2026-10-17）

## 做了什么
在 `.164` 监控台（https://example.com/con/ ）概览里、**DeepSeek 余额卡片正下方**新增一张 **「博查搜索余额」** 卡片：
当前余额（低于 ¥5 变黄、低于 ¥2 变红）、今日消耗、近 7 天日均、近 14 天消耗柱状图、累计采样次数、最后更新时间；每 15 分钟自动刷新。
余额低于阈值时，通过已有的 ntfy 手机推送发提醒（标题「博查搜索余额偏低（¥X.XX）」，6 小时去重；余额恢复后也会推一条「已恢复」）。

## 数据从哪来
- 博查余额接口：`GET https://api.bochaai.com/v1/fund/remaining`，头 `Authorization: Bearer <key>`，返回 `{"data":{"remaining":18.48}}`
- **消耗 = 余额差值**（和 DeepSeek 卡片同一思路）：每次采样记一个余额点，当天「第一个点 − 最后一个点」就是今天花掉的钱；单价 ¥0.036/次，可反推调用次数
- 采集脚本：`.164:/opt/dashboard/bocha_balance.py`，每 15 分钟由 systemd 定时器 `dashboard-bocha.timer` 跑一次（`dashboard-bocha.service`，oneshot，OnBootSec=4min / OnUnitActiveSec=15min / Persistent=true）
- 数据文件：`.164:/opt/dashboard/bocha.json`（当前值 + 今日/昨日消耗 + 近 7 天日均 + 预计可用天数）与 `bocha-history.json`（余额点，保留 120 天、上限 5000 点）
- API Key 存在 `.164:/opt/dashboard/.bocha-key`（600），**不进 git 备份**（沿用 sync.sh 的密钥排除规则）
