## 处置（已实施）
1. **临时止血**：`ssh nas 'docker stop photoprism'`（16:54）。内存立即回落，load 从 79 降到 0.5。
2. **PhotoPrism 加内存上限**（`/opt/photoprism/compose.yaml`，备份 `compose.yaml.bak-内存限制-20261017`）：
   - `mem_limit: 1800m`、`memswap_limit: 2400m` → 最多用 1.8G 内存 + 0.6G swap，超了容器自己被 OOM 重启，不再拖垮整机；
   - `PHOTOPRISM_FFMPEG_SIZE: "1920"` → 转码最大 1080p，降低 CPU/内存峰值；
   - `docker compose up -d photoprism` 重建生效。
3. **AdGuard 健康检查 v2**（`/usr/local/bin/adguard-healthcheck.sh`，备份 `.bak-20261017`）：
   - 1 分钟负载 > 8 时只记日志、不重启（系统卡顿时 DNS 慢是症状，重启只会雪上加霜）；
   - 需连续 2 轮（约 4 分钟）健康检查失败才重启，避免抖动中反复重启；
   - 正常时静默、失败恢复后自动清状态。
4. 夜间 02:00 的 `photoprism-index.service` 原本已是 `nice -n 19 ionice -c 3` 低优先级，保留。

## 2026-10-17 21:40 追加：严格限制 PhotoPrism（按用户要求，保护 .164 上的反向代理/网站）

**背景**：`.164` 除了相册，还跑着 `nginx-proxy-manager`（反向代理，80/443，所有网站入口）、AdGuard（全屋 DNS）、natfrp（内网穿透）、memos、filebrowser、reader、home。PhotoPrism 是唯一可能吃满内存 + 打满 3TB 机械盘 I/O 的服务；它一卡，整台机器被动卡死，网站就全挂。用户要求：**严格限制它**。

### 一、容器硬限制（`/opt/photoprism/compose.yaml`，备份 `compose.yaml.bak-严格限制-20261017-2143`）

| 项 | 旧值 | 新值 |
|---|---|---|
| mem_limit | 1800m | **1200m** |
| memswap_limit | 2400m | **1600m**（最多 400M 换页） |
| cpus | 无限制 | **1.5 核**（J1900 共 4 线程，留 2.5 给反向代理等） |
| cpu_shares | 默认 1024 | **128**（关键容器设为 2048，CPU 竞争时它最低） |
| pids_limit | 无限制 | 512 |
| PHOTOPRISM_FFMPEG_SIZE | 1920 | **1280** |
| PHOTOPRISM_FFMPEG_BITRATE | 默认 | **20** Mbit/s |
| 容器日志 | 无限 | json-file 10m × 3 |

`docker compose up -d photoprism` 重建生效（只重启它自己，反向代理/网站无感）。

### 二、cgroup v2 精细限制（`/usr/local/bin/photoprism-guard.sh` + `photoprism-guard.timer`，每 20 秒重新钉一次；容器重建后自动重新施加）

- HDD `/dev/sda`（8:0）I/O 上限：**读 64MB/s、写 32MB/s、读 80 IOPS、写 60 IOPS** —— 它单独打不满机械盘；
- I/O 相对权重 `io.weight = default 20`（默认 100，最低档）；
- 内存软限 `memory.high = 1000M`（到 1G 就开始回收，硬限 1200M 兜底）。

### 三、整机濒死自动保护（同一个 timer 里）

- 触发条件：`/proc/pressure/io` 的 **full avg60 > 50%** 且 **1 分钟负载 > 25**，连续 2 次（约 40 秒）→ 自动 `docker stop photoprism`；
- 目的：宁可相册暂时不可用，也不让整机卡死（反向代理/网站优先）；
- 恢复：`docker start photoprism`（或重启 .164 后 `restart: unless-stopped` 会自动拉起）；
- 状态文件：`/run/photoprism-guard.bad`（连续计数）、`/run/photoprism-guard.stopped`（触发时间）；日志 `journalctl -t photoprism-guard`。

### 四、swap 保护：优先用 SSD，不再抖动 HDD

- 原状：只有 zram 1.5G + `/nas/swapfile` 4G（在 3TB 机械盘上）——10-16 卡死的元凶就是这块盘被换页打满；
- 现状：启用 SSD 上的 **`/swapfile` 4G（pri=50）**，形成三级：zram(100) > SSD(50) > NAS 4G(10 兜底)；
- `/etc/fstab` 已加（备份 `fstab.bak-严格限制-20261017-2145`），已 `systemctl daemon-reload`；
- 效果：换页优先走 SSD，NAS 机械盘只在极端情况才被用到。

### 五、关键容器 CPU 优先级（`docker update`，规则存在容器配置里，重启保持）

- `npm`（反向代理）、`adguardhome`、`natfrp-service`、`home`、`memos`、`reader`、`filebrowser` → `cpu_shares=2048`（`cpu.weight`≈174）；
- `photoprism` → `cpu_shares=128`（`cpu.weight`≈21）；
- 效果：CPU 争抢时关键服务约 **8 倍**优先。

### 验证（21:45 实测）

### 回滚方法

2. cgroup + 看门狗：`systemctl disable --now photoprism-guard.timer`（脚本保留但不生效）
