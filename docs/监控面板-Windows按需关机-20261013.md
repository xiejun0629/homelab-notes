# 监控台：.155 Windows 主用机改成「可按需关机、离线不告警」

需求（2026-10-13）：.155 是主用机，人经常在外面，机器关着；**关机不应该再报警、再推送**。

## 一、之前为什么会一直吵你

| 来源 | 现象 | 频率 |
|:--|:--|:--|
| 监控台推送（notify.py） | `🔴 仍未恢复：本机 离线（192.168.1.155）` | 首次 + **每 6 小时重推一次**（cooldown 21600s） |
| Gatus 探测 | `Windows .155（SSH）` 连续失败 → ntfy 告警 | 关机即触发 |
| 面板告警条 | 「需要关注」里挂着一条严重：`[🖥️ 机器] Windows .155（SSH）无响应` | 一直红着 |
| 概览四宫格 | 「机器在线 3 / 4」红色、「数据新鲜度 185994 s（最旧：本机）」 | 一直红着 |

## 二、改了什么（核心概念：optional 节点）

`server.py` 的节点表里给 .155 加了标记 `"optional": True`（数据驱动，前端和推送器都读这个字段）：

```python
"win": {
    # optional: 这台工作站是主用机，人不在家就关着。离线属于正常状态，
    # 因此离线不告警、不推送；开机时它的磁盘/温度/服务等照常检查。
    "id": "win", ..., "stale_after": 170, "optional": True,
}
```

| 文件 | 改动 |
|:--|:--|
| `/opt/dashboard/server.py` | 节点表加 `optional` 标记；`stats()` 的 meta 白名单加上该字段（否则前端拿不到） |
| `/opt/dashboard/notify.py` | `evaluate()` 里：optional 节点离线 → **直接跳过**，不产生问题、不推送、不重推 |
| `/opt/dashboard/app.js` | ① `computeAlerts` 离线不算故障；② **指向可选机器的探测永远只作展示**（不计入正常率、不产生告警）；③ 卡片中性样式 + 陈旧数据折叠；④ 概览「机器在线/全站探测/数据新鲜度」口径排除；⑤ optional 且关机的卡片排到最后 |
| `/opt/dashboard/index.html` | `.dot.idle`、`.card.idle`、`.idlenote`、`.prow.skip` 等样式 |
| `/opt/gatus/config/config.yaml` | `Windows .155（SSH）` 端点**移除 `alerts:` 块**（端点保留，Gatus 面板里照常显示机器在不在，只是不再推送） |

**没变的部分（重要）**：.155 开机时，磁盘占用、内存、CPU/NVMe 温度、Defender、更新、失败服务等**照常检查、照常推送** —— 只是"关机"这一个状态被认定为正常。

## 三、验证（.155 现在正处于关机状态，都是真实环境）

**推送器逻辑（直接跑函数，构造快照）**

```
1) 可选机器(win)离线        -> []                        # 不产生任何问题
2) 普通机器(srv2)离线       -> [('srv2:offline', 'crit')]  # 该报的照报
3) 可选机器开机但磁盘 95%   -> [('win:disk:C:', 'crit')]   # 开机后照常告警
4) 可选机器开机且正常       -> []
```

**线上自检**：`20:21:21 [notify] 正常，当前问题 0 项`，`notify-state.json` 的 `problems` 为空。
历史遗留的那条 `win:offline` 是**静默清除**的（先清状态文件再重启服务），所以你不会收到一条莫名其妙的「已恢复」。

**面板**（截图 `监控面板-Windows按需关机-20261013.png`）

- 顶栏：`4 台机器 · 3 台在线 · 本机未开机`，告警条只剩 1 项（服务器2 待重启，橙色警告，无严重项）
- 概览：`机器在线 3 / 4 · 本机未开机（允许）`（灰点，不是红点）；`全站探测 20 / 20`；`数据新鲜度 19 s · 最旧：香港 VPS`
- 「本机」卡片：灰点 + `未开机`，一句提示「这台电脑允许随时关机 —— 未开机是正常状态，不会告警、不会推送」，下面「查看关机前的数据（2.2 天前）」可展开
- 全站探测「🖥️ 机器」组：`3 / 3`，`Windows .155（SSH）` 那行灰显「未开机」，右上角写「20 / 20 正常 · 1 项属可按需关机的机器，不计」
- 窄屏 430px、四卡一行 1600px 均正常

**关机/开机瞬间也不会闪红（两种状态实测）**

关机后有一小段窗口：探测（每 60 s）已经失败，而节点数据要 170 s 才过期 —— 这段时间面板会以为机器还开着，却看到探测失败。为了这段时间也不误报，指向可选机器的探测**永远只作展示**：不计入正常率、不参与告警、不推送。两种状态都实测过：

| 状态 | 探测行显示 | 面板口径 | 告警 |
|:--|:--|:--|:--|
| 机器关着（真实） | 灰显「未开机」 | 全站探测 `20 / 20` · 1 项不计 | 无 |
| 机器刚开机/探测失败（模拟在线） | 灰显「免告警」 | 全站探测 `20 / 20` · 1 项不计 | 无 |

依据：「随时可能关机」的机器，在线与否不是可执行的信号；它自己的健康（磁盘/温度/服务/更新）仍由它自己的 agent 上报，照常检查、照常告警。

**Gatus**：重启后 `configuredProviders=[ntfy]`（其它 15 个端点照旧推送），16 个端点仍在监控，日志中 `Sending ntfy alert` 计数为 0。

## 五、以后要不要给别的机器也开这个模式

任何"允许关机"的机器（例如笔记本、备用机），只要在 `server.py` 的节点表里加一行 `"optional": True`，前端与推送器会自动按同一套规则处理，无需改其它代码。

> 注：该机器的**离线**与**指向它的探测**都不再告警；它开机时的磁盘/温度/服务/更新等真实指标照常告警。文件名里的 `optional` 可以理解为「允许不在线」。
