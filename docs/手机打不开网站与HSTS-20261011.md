# 手机打不开网站 + 已加 HSTS（2026-10-11 晚）

## 事情经过
用户在手机 5G 上打开 `http://example.com/` 报 `net::ERR_CONNECTION_RESET`。

**实测结论：站点是好的，问题在移动运营商链路。**
| 测试点 | 结果 |
|---|---|
| 家里宽带 → `http://example.com/` | 200 |
| 家里宽带 → `https://example.com/` | 200 |
| 家里宽带 → `https://example.com/web/` | 200 |
| VPS 本机 → 本机 80/443 | 200 |
| VPS 上的 frps / .164 上的 frpc | 两个服务都 active，80/443 均在监听 |
| `example.com` 的 AAAA 记录 | 无（排除"手机走 IPv6 撞死"） |

`ERR_CONNECTION_RESET` 是**连接被中途重置**（不是解析失败、也不是 404/502），最典型的成因是
**运营商对「未备案域名 + 香港 IP + 80 端口(纯 HTTP)」做阻断** —— 这个策略在移动网络上比家宽更常见。

## 已做的加固：HSTS
在 .164 的 NPM 里给**所有 443 站点**加了：
```
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
```
- 覆盖 8 个 HTTPS 主机：`example.com`、`memory.`、`network.disk.`、`photo.`、`con.`、`dsh.`、`ledger.`、`video.`
- 效果：浏览器**成功访问过一次 https 之后**，之后一年内凡是这个域名（含所有子域）都自动只用 https，**再也不会去撞 80 端口**
- 注意：HSTS 是"先成功一次 https 才生效"，所以**手机第一次必须用 https 打开成功**

## 文件与回退
- 改动文件：`/opt/web/npm-data/nginx/proxy_host/10-lan-ssl.conf`、`12-jellyfin.conf`
- 备份：`.164:/root/npm-hsts-backup-20261011-175812/`
- 重放脚本（幂等，NPM 若重新生成配置后重跑即可）：`.164:/root/npm-hsts.sh`
- 回退：
```bash
ssh nas 'cp /root/npm-hsts-backup-20261011-175812/*.conf /opt/web/npm-data/nginx/proxy_host/ && docker exec npm nginx -t && docker exec npm nginx -s reload'
```

## 验证记录
8 个域名内网 443 全部返回 `strict-transport-security: max-age=31536000; includeSubDomains`；
公网 `https://example.com/`、`https://example.com/web/`、`https://example.com/con/` 同样带上该头；
`http://example.com/` 仍返回 200（HSTS 只在浏览器侧生效，不改变服务器行为）。

## 如果手机连 https 也打不开
那不是服务器问题，按顺序查：
1. 换浏览器（截图里是 xbrowser，国产浏览器可能自带代理/拦截）或换系统浏览器
2. 切 WiFi 对比（同样是 5G vs 家宽）
3. 用手机浏览器打开 `https://203.0.113.10/` 看是否 IP 层也通（会报证书错误，但能连上说明是域名被拦）
