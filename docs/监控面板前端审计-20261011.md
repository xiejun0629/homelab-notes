## 4. 后端 JSON 字段（实测来源）

### 4.1 `/api/stats`（`server.py:305-326`，字段拼装 313-321）
`{generated_at, server_uptime_sec, nodes:[…]}`；每个 node：
`meta:{id,name,role,host,kind,mode,interval,stale_after}`、`online`（bool）、`age_sec`、`error`、`latency_ms`、`data`（见下）。
`NODES` 定义 4 个节点 `srv1/srv2/win/hk`（`server.py:61-89`）。

### 4.2 节点 `data` 顶层键（`collect.py:1058-1079`）
`collected_at, host{os,kernel,arch}, cpu{usage_pct,model,cores,load,queue_length,per_core?}, temps{cpu_c,nvme_c,hottest_c,chips[],note}, mem{usage_pct,used_mb,total_mb,swap_*,cached_mb,committed_mb}, uptime{uptime_sec,uptime_human,boot_time}, disks[], failed_mounts[{mount,device}], containers{available,error,running[],all[],unhealthy[],restarting[],total,stats_ok}, ports[{port,proto,public,addr,addrs[],procs[],proc,state}], ports_error, services, reboot{required,packages}, procs{by_cpu[],by_mem[]}, sessions[{user,tty,from,login}], errors{recent[],sources[{unit,count}],count_24h,count_1h}, connectivity{gateway,internet,dns,tailscale}, interfaces[{name,state,rx_bps,tx_bps}], web[], minecraft`。
Windows 额外：`gpu{adapters[],engines[{engine,pct}],max_pct}`、`security{defender{available,realtime,signature,last_quick_scan},threats,threats_active,last_detection,firewall[{name,enabled}]}`、`updates{count}`（实测于 `/opt/dashboard/push_win.json`）。

### 4.3 web / smart / services
- **web**：`[{label, url, code, ok, ms, error}]`——字段名实测确认（`collect.py:670-671` 生成；`push_hk.json` 21 条、`push_win.json` 3 条；`srv1` 10 条 / `srv2` 2 条来自 `collect.py:34-53`）。`ok` 仅表示"HTTP 有响应（401/403/404 也算 ok）"，失败时 `code` 为 null、`error` 是异常类名。
- **smart/disk health**：**不存在**。所有 `.py/.js/.html` 中都没有 `smart` / `pending_sectors` 字段（grep 无命中）。真实磁盘对象字段：
  - Linux（srv1/srv2）：`{device,mount,fstype,total_gb,used_gb,free_gb,usage_pct}`（`collect.py:325-330`）
  - Windows：`{device,free_gb,fstype,mount,total_gb,usage_pct,used_gb}`
  - **hk：`{mount,total,used,avail,usage_pct,fs}`（键名不同、值为字符串）** → 前端读 `used_gb/total_gb`（`app.js:306`）显示"—"，见问题 P6。
  - 真实 SMART 数据在旁路：`/opt/smart-check.sh` 写 `/nas/dsh-migration/smart-status.json.sda|.sdb`，字段正是被期待的 `disk, model, health, temperature_c, reallocated_sectors, pending_sectors, offline_uncorrectable, power_on_hours, checked_at, status`（实测 sda：`health=PASSED, pending_sectors=0, power_on_hours=205`）。该文件由 Gatus 轮询（见 `/opt/web/npm-data/logs/proxy-host-1_access.log` 的 `/assets/smart-status.json`），**监控台从未读取它**；要加硬盘健康区必须新增后端读取 + `/api/stats` 字段。
- **services**：`{items:[{name,unit,active,sub,key,description}], failed:[…], system_state, total_loaded, error}`（`collect.py:455-472`；上限 40 条）。
- **alerts / problems**：**后端不返回**。`stats()`（`server.py:322-326`）只有 `generated_at/server_uptime_sec/nodes`；顶部告警条 100% 由前端 `computeAlerts`（`app.js:83-190`）现算。

## 5. 具体布局 / 排序 / 视觉问题

1. **没有"异常优先"排序**：`render(nodes)` 直接 `nodes.map(renderNode)` 顺序输出（`app.js:623`），节点顺序固定为后端 `NODES` 顺序 `srv1→srv2→win→hk`（`server.py:61-89,309`）；故障节点不会上浮，只有 `computeAlerts` 内部排了序（`app.js:188`）。
2. **卡内区块顺序＝实现顺序，不是重要度顺序**：Web 健康探测排在 服务/网络 之后（`app.js:542`）、磁盘又在其后（`:543`）、日志倒数第二（`:550`）、最后再塞一块 Minecraft 摘要（`:551`）。
3. **卡片高度极不均衡，且整卡不可折叠**：`.grid` 为 `auto-fit` + `align-items:start`（`index.html:53`），卡片按内容自然撑高，hk（21 条探测）与 win 卡高度差数倍，右侧留大片空白。
4. **折叠只用在边角内容**：`details()` 仅用于动态端口/仅本机端口/其他服务/CPU·内存 top5（`app.js:356-357,445-446,254`）；主力区块全部常开。
5. **重复/死掉的 CSS**：`.mc .mhead/.mbody`（`index.html:126,128`，前缀 119/121）与 `.mcpanel .mchead/.mcbody`（`:156,159`）是两套外观；`.mcgrid` 与 `.mcgrid2` 一字之差分属不同容器（`:132` 供 `app.js:481` 卡内摘要用，`:160-161` 供 `index.html:232` 面板用）；`.hmeta`（`:27`）、`.tokwarn`（`:192-194`）为死代码。
6. **跨节点字段名不一致导致静默"—"**：hk 磁盘用 `total/used`，前端只读 `used_gb/total_gb`（`app.js:306`），同卡片其它数字正常，容易被误读为"数据缺失"。
7. **延迟没有颜色分级**：Web 探测 chip 只有 `ok/bad` 两档（`app.js:434`，`chip()` 在 `:226`），`ms` 走 `.port small` 灰色小字（`index.html:112`），3000ms 与 50ms 视觉一致；而 CPU/温度有 `pctColor/tempColor`（`app.js:45-56`）。
8. **无阈值线/无最慢排序**：21 条探测一次性平铺，只显示 `ok` 计数（`app.js:542`），没有按 ms 排序、没有 p95、没有"最慢/刚变红"高亮。
9. **告警条与来源割裂**：`#alerts` 在 `#grid` 之前（`index.html:217-218`），条目只写"节点名 + 文本"（`app.js:200`），不可点击、不定位到对应卡片区块，超过 14 条被截断为"另有 N 项"（`:202`）。
10. **硬编码陈旧数字**：`<small id="subtitle">3 台机器</small>`（`index.html:199`）从不被 JS 更新，而实际是 4 台（`server.py:61-89`）；页脚数据源说明同样是硬编码（`app.js:661-663`）。
11. **刷新节奏与节点节奏不匹配**：`REFRESH_MS = 5000`（`app.js:4`），而 `win` 上报 ~65s、`hk` ~120s（`server.py:80,86`）；同一页四个节点新鲜度完全不同，只有卡头一行灰色 `Ns 前`（`app.js:502`）。
12. **"服务"信息重复三层**：`.osline` 的"有失败服务"pill（`app.js:507`）、"服务"区的 `system_state` + failed 列表（`:540` → `:242-244`）、顶部告警条（`:93-96`）。
13. **Minecraft 双份展示**：卡内 mc 摘要（`app.js:472-492`）与底部 `#mcpanel`（`index.html:220-263`）在版本/端口/玩家/运行时长上重叠，卡内摘要还带导航文案（`app.js:490`）。
14. **内联样式散落**：`index.html` 内联 `style=` 至少 9 处（`:208,224,236,238,243,249,252,257,258`），`app.js` 更多（`:306,364,373,388,514,793,803-806,921-923`），改主题需多处同步。
15. **响应式几乎缺失、三列磁贴过窄**：唯一断点 `@media (max-width:860px)` 只改 `.mcgrid2`（`index.html:161`）；`.metrics` 固定三列（`:70`，前缀 63），卡片逼近 392px 时每块磁贴不足 120px，20px 等宽数字（`.metric .val`，`:73`）会挤压换行。

## 6. 改动风险清单（编辑时不能破坏的东西）

- **JS 强依赖的 id（不可改名/删除）**：`#grid`（`app.js:11,623`）、`#alerts`（`:193`）、`#toast`（`:10`）、`#clock/#hdot/#hstate/#hint/#foot`（`:637,654-663,665-667`）、`#whoami/#sessionNote`（`:570-575`）；`#subtitle` 无人引用，安全但会继续显示"3 台机器"。
- **Minecraft 面板 id 全部被就地更新**：`#mcLed/#mcBadge/#mcMeta/#mcStatList/#mcPlayers/#mcPlayersHint/#mcBackupList/#mcConsole/#mcCmdState/#mcCmd/#mcQuick/#mcJob*/#mcBtnBackup` 等（`app.js:730-936`）。面板刻意不做整块 `innerHTML` 重绘以免抢走命令输入焦点（注释见 `app.js:712-716`），**不要把它并入 `render()`**。
- **事件委托契约**：`button[data-act]` + `data-node/data-act/data-target/data-label`（`app.js:227-229,606-610` → `POST /api/action`，`server.py:864-872`）；`#mcPlayers` 的 `data-kick/data-gm`（`app.js:803-804,1005-1020`）；`#mcBackupList` 的 `data-restore/data-del`（`:826-827,1024-1048`）；`#mcQuick` 的 `data-cmd`（`:738,742-745`）。改按钮结构会一次性打断服务/容器重启、踢人、备份回滚。
- **`details[data-k]` 状态保持**：`render()` 依赖 `data-k` 记住展开/收起（`app.js:614-629`），新增折叠区必须给唯一 `data-k`。
- **CSP**：`script-src 'self'`，禁止内联事件处理器与内联脚本（`server.py:718-723`；`app.js:2` 有注释），重构只能用外部 JS 绑定。
- **登录流程**：`goLogin()` 跳 `login`（`app.js:559-562`），`apiFetch` 遇 401 即跳（`:581-585`），`loadSession` 失败进入 6s 重试（`:695-707`）；`login.html:48-60` + `login.js:4-9,37-73` 依赖 `#form/#user/#password/#submit/#msg/#foot` 与 `api/session` 的 `authenticated/user/expires_in/auth_configured`（`server.py:735-742`）。不要把 `apiFetch` 换成裸 `fetch`，否则丢失过期跳转。
- **服务端白名单依赖同一份数据约定**：`run_action` 用缓存数据里的 `services.items[].{name,unit}` 与 `containers.all[].name` 校验（`server.py:383-397`）；重命名这些字段（即使只是为了排版）必须前后端同步。
- **轮询与缓存语义**：`tick()` 同时驱动数据与顶栏状态（`app.js:636-669`），`startPolling` 只启动一次（`:685-693`）；`/api/stats` 是单次全量快照，`mc_console_view` 有 1.5s 缓存（`server.py:475-509`），拆分成多请求时注意。
