## 自动化
```
systemctl list-timers homelab-git-backup.timer     # 看下次触发时间（当前：每天 01:00:12）
systemctl start homelab-git-backup.service         # 立刻手动跑一次
journalctl -u homelab-git-backup.service -n 50     # 看日志
bash /opt/homelab-git/sync.sh                      # 直接在终端跑（同一条脚本）
```
- `homelab-git-backup.timer`：`OnCalendar=*-*-* 01:00:00`、`Persistent=true`（关机错过会在开机后补跑）
- `homelab-git-backup.service`：oneshot、Nice=10、`TimeoutStartSec=3600`
- 脚本 `/opt/homelab-git/sync.sh`；说明 `/opt/homelab-git/README.md`

## 网页是怎么发出来的
脚本每次生成暗色主题 `index.html` → `scp` 到 `.164:/opt/web/npm-data/gitweb/index.html` →
NPM 里加了路由 `location ^~ /git/ { alias /data/gitweb/; index index.html; }`（写在主域 443 与 80 两个 server 块，备份 `/root/gitweb-bak-*`）。
所以 .164 若挂了，网页会 404（仓库本身不受影响，因为仓库在 .223）。

## 网页上的「按文件查改动」搜索框（2026-10-14 加）
- 输入框里可以输**文件名或目录名**（支持多个词，空格分开，例：`dashboard app.js`），也可以选**日期**只看某天的备份；
  快捷按钮：今天/昨天、最近 7 天、最近 30 天、全部时间。
- 结果按「每次备份」分组，列出该文件在这次提交里的状态（新增/改动/删除/改名）、完整路径和提交号；点路径可以直接按那个文件再查一次。
- 「最近的备份记录」里**点任意一行**会展开这次备份改了哪些文件。
- 也能用网址直接查（方便分享/收藏）：
  - 按文件：`https://example.com/git/?q=dashboard/app.js`
  - 按某天的某文件：`https://example.com/git/?q=homer&dt=2026-10-14`
  - 直接展开某次备份：`https://example.com/git/?h=54a3802`
- 实现：备份脚本每次跑时由 `/opt/homelab-git/gen-page.py` 读取 `git log --name-status`，
  把最近 400 次备份的文件清单（上限 6 万条）内嵌进 `page.template.html` 生成静态页，**查询完全在浏览器本地完成**，不需要后端。

## 进展页上的「立即同步」按钮（2026-10-14 加，同日按用户要求从主页挪到进展页）
- 位置：`https://example.com/git/` 页面顶部（KPI 卡片下面那一行）——「**⚡ 立即同步一次**」按钮。
  平时仍然每天凌晨 1:00 自动跑一次，这个按钮是让你**白天想更新时手动跑**。
- 点下去会发生什么：按钮变灰 → 旁边显示「同步中… N 秒」（每 2 秒刷新）→ 跑完显示「✅ 同步完成（N 秒），正在刷新本页…」并**自动刷新**，
  刷新后就能看到这次的新备份记录（也能用「按文件查改动」查这次改了哪些文件）。按钮旁边还显示「上次备份：日期时间　共 N 次备份」。
- 想看实时滚动的日志：点按钮旁边那个「实时日志」链接 → `https://example.com/git/sync/`（那个页面里同样有一个同步按钮）。
- 网址直接触发（适合手机书签）：`https://example.com/git/?sync=1`，打开就自动点一次。
- 组件：
  - `.223`：`homelab-sync-web.service` → `/opt/homelab-git/syncweb.py`（纯 Python 标准库，监听 `203.0.113.10:8099`）
  - `.164`：NPM `location ^~ /git/sync/ { proxy_pass http://192.168.1.223:8099/; proxy_read_timeout 300s; }`（主域 443 与 80 块，备份 `/root/gitsync-bak-*`）
  - 进展页由 `/opt/homelab-git/page.template.html`（模板）+ `gen-page.py`（生成器）产出；`gen-page.py` 会把 `meta/web-token` 注入页面，
    所以点按钮时页面能带上 `X-Token` 调 `/git/sync/run`（令牌文件 600 权限、不进 git）
- 主页（Homer）上**没有**同步按钮，只保留「项目仓库」一个入口（按用户要求，保持 14 个入口的整洁）。
- 防误触/防滥用：同一时间只允许一个同步；两次之间至少间隔 **60 秒**；每小时最多 **20 次**。
  可能看到的提示：「刚同步过，N 秒后再试」「正在同步中，稍等一下」「一小时内已经同步 20 次了，先歇一会儿」。
- 看日志：`journalctl -u homelab-sync-web.service -n 50`（后台服务本身）／`/opt/homelab-git/meta/sync-web.log`（每次同步的完整输出）
- 命令行等价物：`systemctl start homelab-git-backup.service`
## 注意 / 踩坑
1. **。223 对 NAS 共享是只读的**：脚本先 `ssh nas "chmod -R a+rX /nas/dsh-migration/{workspaces,教程,windows-snapshot-20261006}"` 放开权限，再由 .223 拉取；要往 NAS 写文件必须经 .164（scp→cp→chmod 664）。
2. `.164` 上**不存在** `/opt/natfrp`，natfrp 的配置真实路径是 **`/etc/natfrp`**。
3. `... | grep -vE | sed ... || warn` 这种写法会误报（grep 过滤掉全部行时退出码为 1）→ 已改成「输出重定向到临时文件 + `if !` 判断」。
4. 脚本绝不能把 `/opt/homelab-git` 同步进它自己（已在脚本里规避）。
5. **仓库含敏感内容**：`.164` 的 `/root/.ssh/`（含私钥）、监控台 `auth.json`/`token.txt`、DSH 配置（可能含 API Key）。
   仓库**只在 .223 本机**（没有任何远端）。也就是说：它是一份「整机可还原」的备份，**不要 `git push` 到 GitHub 之类的公网仓库**；
   如果以后想推公网，先让我把密钥类文件加进排除清单。
6. `/git/` 网页是**公开地址**（和主页一样无密码），但里面只有目录名、文件名、体积和提交信息，不含口令。

## 回退
```bash
systemctl disable --now homelab-git-backup.timer     # 停掉每天自动备份
rm -rf /opt/homelab-git                              # 删仓库（不影响任何被备份的原始文件）
# .164 上：删掉网页路由
ssh nas "cp /root/gitweb-bak-*/10-lan-ssl.conf /opt/web/npm-data/nginx/proxy_host/ && docker exec npm nginx -s reload"
```
仓库只是**只读复制**原始文件，备份脚本从不修改被备份的源文件。
